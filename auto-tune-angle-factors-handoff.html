Goal

Automatically adjust the Low Speed Adjustment Factor and High Speed Adjustment Factor for Ford angle-mode lateral control while the vehicle is driving, so the user gets a personalised steering feel without manual trial-and-error tuning.

How It Works

Core Idea

The steer loop (10 Hz) compares requested curvature (kappa_cmd from the planner) against actual vehicle curvature (yawRate / vEgo from sensors). The signed error tells us whether the car is understeering (positive error) or oversteering (negative error) relative to the planned path.

Algorithm (per steer-loop tick)

  1. Compute actual curvature: actual_kappa = yawRate / vEgoRaw
  2. Compute error: error = kappa_cmd - actual_kappa
  3. Smooth error: exponential filter with alpha = 0.1 (~10-frame window)
  4. Integrate error: accumulate clamped error (±0.0002 per frame) into a running sum
  5. Threshold check: when integrated error crosses ±0.0008 and at least 150 frames (15 s) have elapsed since the last adjustment → nudge the relevant factor by ±0.01
  6. Persist: write new factor value back to Params, update timestamp and adjustment counter
  7. Reset accumulator: zero the integral and frame counter after an adjustment

Speed Regimes

RegimeSpeed RangeParam Adjusted

Guardrails

  • Curvature must be in trusted range: 0.003 ≤ |kappa| ≤ 0.025 rad/m
  • Speed must be > 5 m/s for meaningful yaw-rate signal
  • Max 1 adjustment per 15 seconds per regime
  • Step size capped at ±0.01
  • Factors clamped to [0.5, 1.5]
  • All accumulators reset when lateral control disengages
  • Disabled by default — user must opt in via toggle

Known Limitations & Open Questions

Telemetry visibility: The telemetry outputs (bp_at_actual_curvature, bp_at_curvature_error, integrals) are stored on the class instance but not yet exposed to any UI element or cereal message. A follow-up could wire these into the developer overlay or a dedicated debug screen so the user can see tuning progress.
Reset on reboot: The integral accumulators and frame counters reset on every reboot (they live in Python instance state). This is intentional — carries no risk — but means the auto-tune starts fresh each drive session. The factor values themselves persist across reboots via Params.
No upper-bound on total adjustments: The system can keep adjusting indefinitely. A possible enhancement: cap total adjustments per session or add a convergence detector that auto-disables after factors stabilise.
Single-axis error: The algorithm uses curvature error only. Lane-centering error (lateral position) is not factored in. A more advanced version could weight both curvature tracking and lateral position error.

How to Continue

  1. Test on vehicle: Enable the toggle, drive varied routes (low-speed curves, highway curves), monitor adjustment counts in Params to verify the system is active.
  2. Adjust constants: If tuning is too aggressive or too slow, tweak _AT_STEP, _AT_INT_THRESH, or _AT_MIN_FRAMES in lateral_angle_ext.py.
  3. Expose telemetry: Wire the bp_at_* outputs into the developer UI overlay or a new debug panel for real-time visibility.
  4. Add convergence detection: If factor hasn't changed in N seconds, auto-disable and notify user that tuning is complete.
  5. Consider lateral position error: Extend the algorithm to also weight lpLane or lateralPosition error for a more complete picture.
