Autotune Debug Guide

Extract curvature-factor tuning data from your device over WiFi and visualise it on your PC.

Overview

The autotune system runs on the device and continuously adjusts two curvature gain factors — low-speed (< 30 mph) and high-speed (> 60 mph) — by integrating the tracking error between the commanded and actual curvature during curves.

Debug logging records all intermediate values at ~2 Hz while in a curve, plus an event every time a factor is adjusted. After a drive you can pull those records off the device and plot them with plot_autotune.py.

ℹ
Logging only fires while autotune is enabled in the BluePilot settings and while the car is in a curve (0.003 < |κ| < 0.040 1/m).

Requirements

  • SSH access to the device over local WiFi
  • Python 3.10+ on your PC
  • matplotlib installed on your PC — pip install matplotlib
  • Autotune enabled in BluePilot → Lateral settings

Quick Start

  1. Take a drive with autotune enabled Drive a route with several turns. The more curves, the more data. Each distinct curve entry increments the curve counter; a factor adjustment fires after 3 curve entries with a consistent error direction.
  2. Connect your PC to the same WiFi as the device The device must be reachable by SSH. Confirm with: 
    ssh comma "echo ok"
    If you connect by IP instead of hostname: 
    ssh root@192.168.x.x "echo ok"
  3. Extract and plot in one command From the root of the sunnypilot repo on your PC: 
    python3 tools/debug/plot_autotune.py --ssh comma
    Or by IP: 
    python3 tools/debug/plot_autotune.py --ssh 192.168.x.x
    The script SSHes to the device, filters the swaglog for autotune events, streams them back, and opens the plot window.

Saving Data for Later

Use --save to cache the extracted records as a local JSON file. You can then replot without reconnecting to the device. 

# Extract and save
python3 tools/debug/plot_autotune.py --ssh comma --save autotune.json

# Replot from saved file (no device needed)
python3 tools/debug/plot_autotune.py autotune.json
✓
Save after every drive to build up a history. Rename files by date (e.g. autotune_2026-06-30.json) to track convergence over time.

Reading Local Swaglog Files

If you copy the device's swaglog directory to your PC via scp you can point the script directly at it: 

# Copy swaglogs off device
scp -r comma:/data/log /tmp/device_logs

# Plot from the local copy
python3 tools/debug/plot_autotune.py /tmp/device_logs

The Plot

Six panels are shown. Each sample on the x-axis is one log point (~0.5 s apart, only during curves).

Curvature (κ)
The three curvature signals. All three should track each other when the tune is converged.
kappa_cmd — what the model requests right now
delayed_kappa_cmd — command from ~270ms ago (what the car is responding to)
actual_kappa — yawRate / vEgo (what the car is actually doing)
Curvature Error
Difference between delayed command and actual. Zero means perfect tracking. A persistent positive error means the car is understeering; negative means oversteering.
raw_error — per-sample (noisy)
error_smooth — exponential moving average (α=0.1)
Integrals
Accumulated weighted error for each factor. When an integral crosses ±0.0008 and there have been ≥3 curve entries, a factor adjustment fires and the integral resets to zero.
integral_low
integral_high
Curvature Factors
The values being tuned. Should converge toward 1.0 when well-tuned. Clamped to [0.5, 1.5]. Vertical tick marks indicate adjustment events.
low_factor (≤ 30 mph)
high_factor (≥ 60 mph)
Blend Weights
How the error is distributed between the two factors at the current speed. At 30 mph w_low=1, w_high=0. At 60 mph w_low=0, w_high=1. Linearly interpolated between.
w_low
w_high
Speed
Vehicle speed in mph. Useful for correlating which factor was active and confirming the drive covered both speed ranges.

Factor Adjustment Table

The script also prints a table of every adjustment that fired during the session: 

=================================================================
                      Factor adjustments
=================================================================
  FordAngleLowSpeedFactor          1.0000 -> 1.0040  step=+0.0100  osc=False  curves=3
  FordAngleHighSpeedFactor         1.0000 -> 0.9960  step=-0.0100  osc=False  curves=3
  FordAngleLowSpeedFactor          1.0040 -> 1.0044  step=+0.0100  osc=True   curves=3
Column Meaning
old_factor → new_factor Factor value before and after the adjustment
step Raw step magnitude (positive = increase, negative = decrease). Scaled by the integral ratio, max 3× the base step of 0.01
osc=True Oscillation detected — the last two adjustments went in opposite directions. Fine alpha (0.08) is used instead of coarse (0.4) to zoom in on the optimum
curves How many distinct curve entries had accumulated before this adjustment fired

What Good Convergence Looks Like

  • actual_kappa tracks delayed_kappa_cmd closely with no consistent offset
  • error_smooth fluctuates around zero without a sustained positive or negative bias
  • Integrals accumulate slowly, reset frequently, and don't consistently saturate in one direction
  • Factor adjustments alternate direction (osc=True), indicating the factor is hovering near optimal
  • Both low_factor and high_factor are stable (not drifting)
⚠
If error_smooth is consistently positive (understeering), both factors will climb. If it is consistently negative (oversteering), they will drop. A factor that hits the 0.5 or 1.5 clamp and stays there indicates the car's physical response is outside the range autotune can compensate for.

Troubleshooting

No autotune_state entries found

Autotune was not enabled during the drive, or the drive had no curves within the curvature window (0.003–0.040 1/m). Enable autotune in BluePilot → Lateral settings and drive a route with moderate curves.

SSH timed out / connection refused

Confirm the device and PC are on the same WiFi network. Try pinging the device: ping comma or ping 192.168.x.x. Make sure the device has not gone to sleep or lost its WiFi connection.

SSH error: Permission denied (publickey)

Your SSH key is not authorised on the device. Add your public key: ssh-copy-id comma, or check that ~/.ssh/config has the correct identity file for the device.

matplotlib not available

Install it on your PC: pip install matplotlib. The script will still print the adjustment table without it.

Only a handful of samples even though I drove a long route

Logging only fires while in a curve (kappa within the window) at 2 Hz. Straight highway driving produces no samples. This is expected.
